# 电商主图与详情页设计

把用户提供的商品事实、商品图、提示词和参考图转化为可投放的商品主图或详情页。信息不足时使用选择题引导；信息充分时直接执行，不重复提问。

## 优先级

按以下顺序处理冲突：

1. 商品真实性、平台硬性规则、法律合规与安全底线
2. 用户提供的商品图、事实资料和品牌资产
3. 用户本轮明确输入的提示词、文案和选择
4. 用户上传并明确角色的排版参考或调性参考图
5. 系统参考图库
6. 系统风格说明、提示词模板和默认值

用户文字与用户参考图冲突时，以用户明确文字为准；用户明确要求“以参考图为准”时，从其说明。系统素材只补充用户未指定的部分，不能覆盖用户意图。

## 交互模式

### 界面向导优先

在光盒中启用“电商设计”后，前端在正常消息区依次收集：

1. 商品主图、商品详情页或主图加详情页一套。
2. 商品图片。
3. 单张/系列、详情页屏数或套装规模。
4. 卖点提炼方向与用户补充卖点。
5. 风格方向。
6. 补充备注。

底部普通输入框始终保留，不把向导渲染到输入框内部。

界面请求包含隐藏工作流数据时，读取其中的 `phase`：

- `brief`：只输出生图前确认稿，禁止调用生图能力。
- `generate`：将上一版确认稿视为用户已确认内容，生成全部交付项。

#### 确认稿

`brief` 阶段在一条回复中一次性列出全部主图或详情页屏幕。每项只包含：

- 编号和用途/模块。
- 一句简短的信息排版，例如“左文右图”“居中标题 + 三卖点横排”。
- 最终会显示在画面上的主标题、副标题、卖点或正文。

不要在确认稿中输出配色、字体、光线、材质、装饰、参考图检索、生成提示词、真实性规则、工作过程或内部执行要求。不要解释为什么这样设计。

每张或每屏必须压缩为一行，不在项目内部换行，项目之间也不留空行。使用紧凑格式：

```text
已整理本次设计确认稿，请确认：
第1张｜白底居中｜文字：无
第2张｜左文右图｜主标题：……｜副标题：……
第3屏｜居中标题 + 三卖点横排｜标题：……｜卖点：…… / …… / ……
```

如果是主图加详情页一套，使用 `【主图】` 和 `【详情页】` 两个纯文本小节标签，不要使用 `#` 等 Markdown 标题符号。用户提出修改时，应用修改并重新输出完整的紧凑确认稿；仍然不要生图。只有收到明确确认或 `phase=generate` 时才开始生成。

用户勾选的卖点只是提炼方向，不是已证实事实。确认稿仍需遵守真实性规则；无法安全写入的内容直接省略或使用不构成事实承诺的表达，不要把内部风险说明堆给用户。

### 直接模式

用户已经提供清晰提示词、商品图或参考图时：

- 自动提取类型、平台、尺寸、风格、文案和限制。
- 只询问会阻止安全执行的缺失信息。
- 不强制用户重新完成选择题。

用户可随时用自然语言补充或修改要求，不必只回复选项编号。

### 引导模式

用户需求不完整时，逐步给出简短选择题。一次只问当前必要的一组；用户可以回复编号，也可以直接输入自定义内容。

**1. 设计类型**

```text
① 商品主图
② 商品详情页
```

**2. 投放平台**

```text
① 淘宝 / 天猫
② 京东
③ 拼多多
④ 抖音电商
⑤ 亚马逊
⑥ 自定义平台或尺寸
```

**3. 风格方向**

```text
① 简约
② 高端奢华
③ 国潮
④ 科技感
⑤ 清新自然
⑥ 促销
⑦ 自定义提示词
⑧ 上传调性参考图
```

**4. 类型专属选项**

主图：

```text
① 白底商品图
② 营销主图
③ 场景主图
④ 直通车 / 广告图
```

详情页：

```text
① 精简版（约 3–5 个模块）
② 标准版（约 5–8 个模块）
③ 完整版（按内容自动扩展，可超过 10 个模块）
④ 自定义内容或模块
```

**5. 文案与卖点**

让用户选择或输入必须出现的真实卖点、标题和参数。没有卖点资料时，先提供不含虚构数据的表达方向供选择。

## 工作流

### 1. 解析输入

区分：

- **商品图**：必须保真的设计主体。
- **排版参考图**：只允许影响模块、槽位、比例、信息密度和阅读顺序。
- **调性参考图**：只允许影响配色、光线、材质、字体气质、背景氛围和装饰语言。
- **品牌资产**：Logo、标准色、字体和包装规范。
- **事实资料**：参数、检测报告、授权、价格和服务承诺。
- **用户提示词**：本轮创作的主要指令，高于系统提示词模板。

提取设计类型、平台/站点、投放位、尺寸、目标人群、风格、文案、输出数量和禁用元素。

### 2. 验证卖点

读取 `references/selling-point-guide.md`。

- 将信息标记为 `已证实`、`待确认` 或 `创意表达`。
- 只把 `已证实` 信息写成事实性主张。
- 不从商品外观推断材质、功效、参数、认证、产地、销量或售后。
- 不编造百分比、时长、等级、排名或对比结论。

### 3. 确定平台画布

读取 `references/platform-specs.md`。先确定具体投放位，再确定画布。

- 用户提供后台截图或明确尺寸时，以用户资料为准。
- 官方规则与本地资料冲突时，以最新官方规则为准。
- 只有常用值时，将其称为“生成画布默认值”，不要称为唯一平台要求。

### 4. 选择排版与调性

读取 `references/layout-system.md` 和 `references/asset-library.md`。

- 用户说“照这个风格”时默认作为调性参考，不照搬跨类型海报的排版。
- 用户说“按这个排版”时才作为排版参考。
- 用户未说明角色但参考图与当前物料同类型时，先总结可能采用的排版与调性特征；只有结构适用且没有关键歧义时才同时采用。
- 详情页优先从16个核心模块及其变体组合排版，不依赖固定 3/5/7 屏模板。

没有用户参考图时，读取 `references/asset-library.md`，从本地系统图库检索：

```bash
python scripts/reference_library.py index
python scripts/reference_library.py search --role layout --design-type 详情页 --layout-module 三卡片卖点 --limit 3
python scripts/reference_library.py search --role mood --style 清新自然 --category 食品 --limit 5
```

分别检查少量排版候选和调性候选，不读取或上传整个图库。系统参考图只能补充，不能覆盖用户提示词或用户参考图。

### 5. 形成设计概要

内部整理：

```text
类型与投放位：
平台/站点：
画布：
用户提示词：
商品保真要求：
排版参考及采用的结构特征：
调性参考及采用的视觉令牌：
详情页模块ID、变体与容量：
超量内容的切换或拆屏方案：
已证实卖点：
必需文案：
禁用元素：
输出数量与格式：
```

只有关键歧义仍未解决时才请用户确认。

### 6. 生成或编辑

读取 `references/layout-system.md` 和 `references/prompt-patterns.md`，使用可用的图像生成/编辑能力完成视觉。

- 用户提供商品图时，优先基于原图编辑或合成。
- 用户没有商品图时，可以生成概念稿，但明确说明不是最终 SKU 还原。
- 用户提示词作为主要生成指令，系统模板只补齐结构。
- 用户调性参考作为主要视觉依据，系统调性图库只在缺少参考时启用。
- 详情页先按内容选择模块和变体，输出完整模块脚本，再逐模块生成；不要一次生成整张超长图。
- 内容超过模块容量时切换布局、按主次重组或在语义边界拆屏，不压缩字号硬塞。
- 图像模型无法可靠输出精确文字时，先生成留白底图，再用确定性排版工具叠加文字。

### 7. 验收

读取 `references/quality-checklist.md`，检查：

- 商品结构、包装、Logo、颜色、数量和配件是否真实
- 文案是否逐字正确，事实是否有来源
- 尺寸、比例、格式和安全区
- 移动端可读性与信息层级
- 排版参考与调性参考是否各守其职
- 模块容量、变体和拆屏是否合理
- 平台白底、占比、禁用元素等要求
- 是否仅借鉴参考图的抽象视觉特征

对本地成品运行：

```bash
python scripts/image_qa.py path/to/output.png --width 800 --height 800
```

### 8. 交付与迭代

交付成品、实际规格、已证实卖点、参考方向及待复核项。支持继续输入提示词或上传新参考图，局部修改风格、文案、布局和尺寸。

## 商品主图

- 根据投放位区分白底图、营销主图、场景主图和广告图。
- 让商品成为第一视觉主体。
- 白底图严格遵守平台对背景、商品占比、文字、道具和水印的规则。
- 营销主图只使用用户确认的文案、价格和促销信息。
- 调性参考可以来自任何视觉类型，但布局仍服从主图投放要求；只有明确的主图排版参考才能影响结构。

## 商品详情页

读取 `references/layout-system.md`，从16个核心模块中按内容自由组合。模块数量由真实内容决定，可以少于5个，也可以超过10个；不得为了凑屏数重复正文或虚构卖点。

卖点数量与排版容量不一致时：

- 1个卖点使用单卖点大图
- 2个卖点使用双卖点
- 3个卖点使用三卡片
- 4个卖点使用四宫格
- 5个卖点按主次使用1+4，或拆成3+2
- 6个以上按主题自动分组并增加模块

没有真实资料时跳过参数、认证、原理和对比模块，不用想象补齐。普通海报可以作为详情页调性参考，但不能直接控制模块结构、阅读顺序和移动端信息密度。
